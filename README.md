# CraftFlow Flutter

تحويل واجهات CraftFlow إلى تطبيق Flutter عربي باتجاه RTL.

## ملخص Publish release

يتضمن هذا الإصدار تجربة أولية متكاملة لإدارة الورش الحرفية، وتشمل:

- تجربة بدء استخدام عربية باتجاه RTL تتضمن Splash وOnboarding واختيار نوع الورشة.
- دعم ثلاث ورش: النجارة، الحدادة، والألمنيوم، مع 27 شاشة متخصصة.
- تنقل موحد عبر NavigationBar وDrawer للوصول السريع إلى الرئيسية والمعرض والطلبات وأدوات الورشة.
- إنشاء طلبات تفصيل مخصصة مع إدخال الاسم والوصف والخامة والمقاسات وإضافة المرفقات.
- حفظ الطلبات وحالتها والمخزون محلياً عبر SharedPreferences.
- شاشات تشغيلية لمعرض الأعمال، موازنة الأحمال، الخط الزمني للإنتاج، لوحة الفني، المخزون، الجودة، التسليم والضمان.
- تصميم موحد بخط Cairo وثيم مخصص ومكوّنات مشتركة لنماذج الطلبات والنوافذ السفلية.

ملاحظة: يستخدم الإصدار الحالي بيانات تجريبية محلية، بينما تم تجهيز طبقة API لربط الخادم الحقيقي لاحقاً.

## Architecture

يتبع التطبيق تقسيمًا قريبًا من Clean Architecture:

- `lib/core`: الثيم والألوان والخدمات المشتركة.
- `lib/domain/entities`: نماذج المجال مثل `Workshop`.
- `lib/data/services`: التكامل مع API عبر `ApiService`.
- `lib/presentation/screens`: شاشات البداية، النجارة، الحدادة، والألمنيوم في ملفات مستقلة.
- `lib/presentation/widgets`: المكوّنات المشتركة مثل `FeaturePage` و`SheetModal`.
- `lib/main.dart`: Composition root للتطبيق، يركّب الطبقات ويعرّف التنقل فقط.

## الشاشات والتنقل

يحتوي التدفق الكامل على 27 شاشة:

- 3 شاشات بداية: Splash وOnboarding وAuth Gate.
- 8 شاشات للنجارة.
- 8 شاشات للحدادة.
- 8 شاشات للألمنيوم.

تتوفر الشاشات الثماني الخاصة بكل ورشة من Drawer، بينما تعرض NavigationBar الصفحة الرئيسية والمعرض والطلب الجديد. يحتوي كل مسار على AppBar موحد، وتستخدم الطلبات SheetModal مشتركة، مع اتجاه RTL وخط Cairo مخصص.

## API Integration

غيّر العنوان داخل `ApiService.getWorkshopSummary` إلى عنوان الخادم الحقيقي، ثم أضف المصادقة وواجهات الطلبات بحسب عقد API الخاص بالمشروع. حالياً يستخدم التطبيق بيانات تجريبية حتى يعمل التصميم دون خادم.

## التشغيل

بعد تثبيت Flutter وإضافته إلى PATH من مجلد المشروع:

```powershell
flutter pub get
flutter run
```

للتشغيل على Edge بعد إنشاء ملفات المنصة:

```powershell
flutter run -d edge
```

1. التحقق من الملفات المعدلة والجديدة:

git status

2. تجهيز جميع التغييرات للإضافة:

git add .
3. حفظ التعديلات برسالة توضيحية:

git commit -m "تحديث إعدادات المشروع وربط الخدمات" 

4. سحب أي تحديثات موجودة على GitHub (لتفادي التعارض):

git pull origin main

5. رفع التعديلات النهائية إلى المستودع:

git push origin main
